# `purchase_quotes`

## Searchable Aliases
vendor bids, procurement proposals, pricing requests, supplier quotes

## Description
The `purchase_quotes` table manages the specialized **Inter-Store Handoff** logic. In a multi-warehouse organization, one branch (Store A) often buys inventory from another branch (Target Store). 

Because these are legally/financially distinct entities within the system, this table acts as the bridge that synchronizes the "Request to Buy" from one store and the "Quote to Sell" from the other. It ensures that internal transfers are tracked with the same rigor as external vendor purchases.

## ⚙️ The Inter-Store Workflow
1.  **Request**: Store A (the requester) identifies a need and creates a `purchase_quote` targeting a `target_store_id` (the supplier store).
2.  **Internal Quote**: The target store reviews the request and responding with availability and internal pricing.
3.  **Handoff Linkage**: 
    *   The system creates a `sales_order_id` for the **Target Store** (they are selling).
    *   The system creates a `purchase_order_id` for the **Originating Store** (they are buying).
4.  **Synchronization**: Status changes to the internal quote (e.g., shipping updates) are mirrored across both linked orders.

## ⚠️ SQL-Critical Behaviors
- **Cross-Store Bridge**: This is one of the few tables where two different `store_id` values are fundamentally linked in a single transaction.
- **The Linked Order Pair**: The presence of both a `purchase_order_id` and a `sales_order_id` defines an **Internal Trade**. If the `sales_order_id` is NULL, the quote has not yet been accepted by the target store.

## Columns (8 Total)

| Column | Type | Nullable | Default | Business Description |
|--------|------|----------|---------|----------------------|
| id | uuid | no | — | Primary key. |
| created_at | timestamptz | no | — | Request creation timestamp. |
| updated_at | timestamptz | no | — | Last synchronization timestamp. |
| store_id | uuid | no | — | **Originating Store**: The branch requesting the stock. |
| target_store_id | uuid | no | — | **Supplier Store**: The internal warehouse providing the goods. |
| purchase_order_id | uuid | no | — | Link to the buyer's purchase contract in `purchase_orders.id`. |
| sales_order_id | uuid | yes | — | Link to the seller's sales contract in `sales_orders.id`. |
| status | enum | no | — | **Handoff State**: (Example of actual values includes: `PENDING`). |

## Common Query Patterns
```sql
-- Find all outstanding inter-store purchase requests
SELECT purchase_order_id, target_store_id 
FROM purchase_quotes 
WHERE status = 'PENDING';

-- List the internal sales orders generated by a specific branch's requests
SELECT sales_order_id 
FROM purchase_quotes 
WHERE store_id = '<your_branch_uuid>';
```
