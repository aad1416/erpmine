# `field_service_tickets`

## Searchable Aliases
service requests, support cases, incident reports, customer issues, help desk, site visits

## Description
The `field_service_tickets` table is the command-and-control hub for the specialized technical support and repair lifecycle within the **Lyndom** (the current PostgreSQL ERP) system. It manages the communication between the customer, the service technician, and internal departments (Engineering, Sales, Purchasing).

Unlike a generic "Help Desk" ticket, a Field Service Ticket in this ERP is a **Technical Lifecycle Document**. It anchors specific repairs to unique physical assets (`units`) and serves as the primary data source for **Root Cause Analysis (RCA)** and warranty recovery.

## ⚙️ The Technical Service Workflow
1.  **Initiation**: A ticket is created in `NEW` status, linked to a specific `unit_id` (Serial Number) and `sales_order_id` (Commercial Contract).
2.  **Triage**: The creator can flag the ticket for `engineering_help` or `purchasing_help` if complex parts or technical redesigns are required.
3.  **Repair/Execution**: Technicians are assigned and tasks are generated. Labor is logged against the `unit_id` in the `timelogs` table.
4.  **RCA Reporting**: Before a ticket can be set to `COMPLETED`, the system mandates the documentation of the Root Cause Analysis (Problem, Cause, and Prevention).
5.  **External Procurement**: If specialty parts are needed, the ticket links directly to a `purchase_order_id`, tracking the arrival of materials needed to finish the repair.

## ⚠️ SQL-Critical Behaviors
- **Mandatory Accountability**: The `rca_report_info_...` columns are mandatory (`not null`). This ensures the ERP captures the "Technical memory" of every failure, essential for ISO-level quality management.
- **Visibility Control**: The `customer_visibility` flag determines if the internal technical notes and progress are exposed to the client portal.
- **Cross-Service Linking**: Many tickets link back to an original `rma` (Return Authorization), completing the loop between "Goods Arrival" and "Repair Resolution."

## Common Query Patterns
```sql
-- Identify all "Stuck" tickets waiting on Purchasing help
SELECT number, title, date 
FROM field_service_tickets 
WHERE purchasing_help = true AND status != 'COMPLETED';

-- Audit Failure Trends: List RCA causes for a specific product category
SELECT unit_item_no, rca_report_info_cause_identification 
FROM field_service_tickets 
WHERE unit_item_category_name = 'Lighting Systems';
```
